# Assumptions, Risks and Limitations — Violet V4

## Assumptions

- The primary value proposition is curated multi-house fragrance discovery, not discount marketplace scale.
- Target shoppers value low-risk sampling and mood-led guidance; this is a professional hypothesis, not measured user research.
- Existing fictional houses/products may be expanded with concise prototype content.
- Desktop quality is more important than mobile in V4 current scope.

## Risks

### R1 — “Luxury” becomes editorial but less shoppable
Mitigation: buying desk/price/sample/full-bottle remain conventional and above story.

### R2 — New Houses/Discovery routes expand scope too far
Mitigation: representative gate first; static data and vanilla architecture; keep utilities simple.

### R3 — Remote stock photography breaks fictional brand credibility
Mitigation: media contract, brand-neutral screening, no visible third-party labels; explicitly prototype status.

### R4 — Sampling UI implies real fulfillment
Mitigation: System Reality labels and visible prototype note; no redeem/free-sample promises.

### R5 — CSS layer drift
Mitigation: identify owner rules before editing; consolidate/supersede rather than stacking arbitrary overrides; spec/code review in Phase 2.

### R6 — Reference Frankenstein
Mitigation: one Violet DNA; each reference has a job; reject non-transferable brand surfaces.

### R7 — No analytics/user research
Mitigation: label audience hypotheses; verify task clarity through heuristic/browser evidence only; do not claim conversion improvement.

## Limitations

- No mobile/tablet V4 completion claim.
- No Safari/Firefox verification in current prototype scope.
- No real payment/order/sample fulfillment/auth/CMS.
- No final rights-managed fictional product photography yet.
- No field performance or conversion measurement.

These limitations do not block Phase 1 because the Design Contract does not depend on pretending they are resolved.
