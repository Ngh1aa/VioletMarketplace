# Responsive / Browser Strategy — Violet V4

## Declared scope

`desktop_only`

### Viewports due in V4

- 1280×900 — lower desktop pressure point.
- 1440×1000 — primary review viewport.
- 1600×1000 — wide desktop pressure point.

Tablet/mobile: `N/A_JUSTIFIED` for current visual-completion claim. Existing small-screen behavior should not be intentionally broken, but no V4 mobile polish or “fully responsive” claim is permitted.

## Browser

Chromium is the declared verification browser for interactive prototype V4.

## Desktop pressure rules

At each declared width:
- no horizontal overflow;
- nav/search/bag remain usable;
- Home featured object retains safe crop;
- PLP rail + three-column grid does not create unreadably narrow cards;
- PDP buying desk actions remain visible/usable without collision;
- House/Discovery compositions preserve hierarchy rather than collapsing into accidental whitespace;
- sticky owners do not cover content;
- text wrapping does not detach price/action from owning product.

## Media

Primary Home/PDP `cover` behavior needs per-asset crop contract verified at all three widths. Product-card ratio may remain fixed 4:5 if focal subject survives.

## Future scope

If a later phase changes to `responsive_all`, mobile/tablet transformation must be designed as a new scope item; desktop screenshots cannot be used as evidence for it.
